# 单人 4 天执行计划（凉径 Lite）

> 前提：1 个人 + DSH agent(s)。不用 relay、不用等队友。
> 核心策略：**砍到能演示，再往上加**。先有一条能跑通的完整链路，再谈精细。
> 当前数据基线（已定稿）：OSM 官方校园多边形 **1.20 km² / 114 顶点**；校内 **285 栋**（21 栋有楼层数 / 264 栋估算 12 m）、**613 条道路边 / 474 节点 / 143 独立回路**；演示日 **2026-11-02**，31 帧；14:00 主结论 **多走 44 米，少晒 4.0 分钟**。

## Day 1（最重要的一天）

### 上午：跑通真实数据 + 校园裁切验证

```powershell
python tools\build.py sample    # 先验证界面链路（不需要网络）
python tools\build.py osm       # 主路径：OSM 主 API，约 3.6 秒
python tools\build.py all       # 阴影 + 路线
node tools\smoke.js             # 应为 173 条全过
```

跑完先验证**五个数**（不对就先别往下做）：

| 检查项 | 期望值 | 从哪看 |
|---|---|---|
| 校园面积 | **1,201,723 m²（1.20 km²）** | `data/meta.js` 的 `campus.area_m2` |
| 校园边界顶点 | **114** | `data/meta.js` 的 `campus.ring.length` |
| 校内建筑 | **285**（其中 `osm_levels` **21** / `estimated` **264**） | `data/buildings.js` |
| 道路 | **613 条边 / 474 节点 / 143 独立回路** | `data/routes.js` 或 `build.py` 运行输出 |
| 演示日帧数 | **31**，首帧 07:00、末帧 17:00 | `data/meta.js` 的 `frames` |

**为什么先验这五个**：范围换过一次（从矩形 bbox 改成校园多边形），任何一个数不对，后面所有文档和 PPT 全错。**1.20 km² / 285 / 613 / 143 / 31** 是新的"五个地基数字"。

**同时确认路线不越界**：`data/meta.js` 里有 `campus`，`smoke.js` 的 7 条校园边界断言会查（含"边界环点数 ≥ 3"；建筑质心在校内、路线采样点在校内、阴影环与校园有交集）。跑 smoke 就是最快的验证。

### 下午：摸清高度补录机制（不要贪多）

1. 打开 `data/height-report.csv`（**60 行 6 列**，第一行「伍舜德图书馆」）。
2. 只填**演示路线两侧、看得见层数**的楼：前 10 行足够，填"人工高度(填这里)"列。
3. 抄进 `tools/build.py` 的 `HEIGHT_OVERRIDES = {way_id: 高度}`，重跑 `shadows` + `routes`。
4. 看 14:00 卡片数字变化（44 米/4.0 分钟可能会微调，**以重跑后的为准**，然后同步改文档口径）。

**验收**：`HEIGHT_OVERRIDES` 至少 5 栋；`estimated` 数量减少；页面 14:00 数字仍然合理（不会因为补高度把结论翻掉）。

## 出问题时的保底顺序

1. 数据没跑出来 → `sample` 模式演示界面链路，PPT 里换成 sample 截图（说明是示例数据）。
2. 高度没补完 → 不影响，诚实说"93% 是 12 m 估算"。
3. 实拍没拍 → 用"阴影 vs 太阳"的地图截图替代，讲稿里删掉实拍那段。
4. 时间不够 → 砍到 6 页：封面 / 14:00 对比 / 拖时间 / 校园边界+日期两个决策 / 可信度 / 边界。
5. 现场设备打不开 → 放录屏。
