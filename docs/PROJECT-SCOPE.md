# 项目范围定义（PROJECT-SCOPE）

> **用途**：在选技术栈、写代码之前，先定清楚"做什么、不做什么"。
> **怎么用**：4 个人各自填自己关心的部分 → lead 汇总 → 一次 30 分钟会议敲定 → 提交进仓库。
> **原则**：这份文档没定稿之前，不写业务代码。改需求要改这里，不要口头改。

## 7. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 技术栈没人熟 | 进度慢 | 选最熟的，不选最潮的 |
| 需求反复改 | 返工 | 以本文档为准，改需求必须走 lead 广播 |
| 某人进度落后 | 阻塞合并 | 任务粒度小 + 每天同步一次 |
| 网络/工具问题 | 浪费时间 | relay + GitHub 已就绪，遇卡就发 blocker |
