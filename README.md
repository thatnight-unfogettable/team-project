# 凉径 · ShadeRoute Lite

> **多走 44 米，少晒 4.0 分钟。**
> 中山大学广州校区南校园「热浪天走哪条路」决策工具。一次离线预计算，前端纯静态查表，零网络、零后端。
> 范围：OSM 官方校园多边形（`way 300917756`）**1.20 km² / 114 顶点**；校内 **285 栋建筑 / 613 条道路边**；演示日 **2026-11-02**，07:00–17:00 共 **31 帧**。

## 1. 它回答什么问题

> 14:00，从**老年人活动中心**走到**岭南学院**（直线约 850 米）。地图给的是最快的路，但它让你**在太阳下走 14 分钟**。

| | 用时 | 暴晒 | 长度 | 阴影覆盖 |
|---|---|---|---|---|
| 最快 | **14.8 分钟** | **14.0 分钟** | 1113 米 | **6%** |
| 阴凉 | **15.4 分钟** | **10.0 分钟** | 1157 米 | **35%** |

**多走 44 米，少晒 4.0 分钟；阴影覆盖 6% → 35%，多换约 344 米阴凉。**

> 这张表来自 `data/routes.js` 的 14:00 帧（pair0）。卡片上的分钟是**取整显示**（14.8 → 「15 分钟」）。

第二组起终点（学生饭堂 → 老年人活动中心，14:00）：**17.6 分 / 16.5 暴晒 / 1320 米 / 6%** vs **18.4 分 / 13.2 暴晒 / 1377 米 / 28%** → **多走 57 米，少晒 3.3 分钟**（卡片显示「18 分 / 17 暴晒」→「18 分 / 13 暴晒」）。

### 1.1 能做什么

| 功能 | 说明 |
|---|---|
| 两条示范路线对比 | 默认 14:00「老年人活动中心 → 岭南学院」，可切第二组 |
| **任意两点查询** | **53 个校园地名下拉**（怀士堂、黑石屋、岭南学院、伍舜德图书馆…），**或地图上点两下**（第一下设起点、第二下设终点，吸附 120 米内道路节点）；**浏览器现场跑 Dijkstra，不发任何请求**，卡片右上角标「现场计算」，并显示「全长 xx 米」 |
| 拖动时间 | 31 帧，07:00–17:00，阴影随之重算 |
| 低置信度提示 | 太阳 < 15° 的 5 帧亮黄色横幅 |
| 离线 | 双击 `index.html`，网络面板 0 请求 |

> "现场算"不是另一套近似：`data/graph.js` 把全部路网 + **31 帧 × 613 条边的暴晒千分比（0–1000）**发给浏览器，`js/router.js` 用同一套边权在页面里跑 Dijkstra。冒烟测试对 **2 对起终点 × 31 帧 = 62 个组合**逐个对拍，与 Python 预计算的最大差 **0 米 / ≤0.05 分钟**。

### 1.2 拖时间，结论会变（这是产品的核心，不是彩蛋）

| 时刻 | 太阳高度 | 少晒 | 多走 | 卡片文案 |
|---|---|---|---|---|
| 07:00 | 5.3° | **0.9 分钟** | 110 米 | 多走 110 米，少晒 0.9 分钟。 |
| 10:00 | 40.5° | 3.3 分钟 | 46 米 | 多走 46 米，少晒 3.3 分钟。 |
| **12:00** | **52.1°** | **2.5 分钟（全天最低）** | 29 米 | 多走 29 米，少晒 2.5 分钟。 |
| **14:00（默认）** | **43.6°** | **4.0 分钟** | **44 米** | **多走 44 米，少晒 4.0 分钟。** |
| 16:00 | 22.3° | 4.3 分钟 | 43 米 | 多走 43 米，少晒 4.3 分钟。 |
| **16:40** | **14.0°** | **6.2 分钟（全天最高）** | 43 米 | 多走 43 米，少晒 6.2 分钟。 |
| 17:00 | 9.7° | 4.7 分钟 | 43 米 | 多走 43 米，少晒 4.7 分钟。 |

- **不是单调的**：14:00 是 4.0，14:20 跳到 4.8（多走 126 米）；因为"两条路差不多好"时算法会在等价解之间整体切换。

- **低置信度**：太阳 < 15° 的 5 帧（07:00 / 07:20 / 07:40 / **16:40** / 17:00）界面亮黄色横幅；16:40 的 6.2 必须带这一句。
- 校园全部道路阴凉占比（613 条边）：07:00 **61.9%** / 09:00 31.7% / **12:00 14.7%** / **14:00 19.8%** / 16:40 42.9% / 17:00 51.3%。

## 2. 怎么跑

```powershell
# 1) 假数据：只验证界面链路（无网络、秒级）
python tools\build.py sample

# 2) 真实数据（三级方案，按顺序试）
python tools\build.py osm        # 主路径：OSM 主 API，一次约 3.6 秒（含校园多边形）
python tools\build.py fetch      # Overpass 优先，任一镜像失败自动降级到 OSM 主 API
python tools\build.py import buildings.json ways.json   # 全都不通时：手动导出的 Overpass JSON
python tools\build.py check      # 只测 Overpass（诊断用，不拉数据）

# 3) 预计算
python tools\build.py all        # osm/fetch + 阴影 + 路线
```

- **零依赖**：Python 3.8+ 标准库，不装任何包（没有 shapely / geopandas / numpy / requests / tqdm）。
- **零网络**：`index.html` 双击即用，页面不发任何请求；OSM 数据在构建阶段一次性拉取。
- **Overpass 的坑**：本机网络下 Overpass 的 POST 会被 TLS 中断（`SSL: UNEXPECTED_EOF_WHILE_READING`），所以主路径是 OSM 主 API；`fetch` 会自动降级。
- **校园裁切**：`tools/build.py` 的 `CAMPUS_ONLY = True`，建筑按质心、道路按路段中点过滤；原始 bbox 数据留在 `data/raw/`。

## 6. 明确不做什么（写下来防跑偏）

- **不做"降温几度"**：那要 Tmrt 模型（长波辐射、风、湿度、衣着），不是这个工具的量级。
- **不做绝对阴影面积承诺**：高度 93% 是 12 m 估算，误差方向双向。
- **不承诺"任何两点都值得绕"**：短距离（如 怀士堂 → 黑石屋 **298 米**）四个时刻两条路几乎一样（少晒 0.0~0.1 分钟）；阴影规划只对**长距离、且有平行道路**的场景有意义——1113 米横穿校园才有 4.0 分钟空间。我们不夸大。
- **不把路线画到校园外**：OSM 官方边界裁切，`CAMPUS_ONLY = True`。
- **不做路线规划 App**：只做"同一时刻两条路线的取舍对比"。
- **不接实时 API**：离线是卖点。
- **不引入框架/依赖**：零 npm、零 CDN。

## 7. 技术要点（面试/答辩可直接用）

1. **研究范围用 OSM 官方校园多边形**（`way 300917756`，1,201,723 m² / 114 顶点），不是矩形 bbox：建筑按**质心**、道路按**路段中点**裁切，保证路线不跨出校门。bbox 内 555 栋 → 校内 **285 栋**（剔除 270 栋）。
2. **太阳位置**：NOAA 简化算法本地计算，1950–2050 内约 0.01°；2026-11-02 12:00 高度 **52.1°**、07:00 **5.3°**。
3. **阴影**：建筑视为竖直棱柱，`L = h / tan(高度角)`（上限 500 m），轮廓 ∪ 平移轮廓取**凸包**（Andrew 单调链）；点在阴影内用**射线法**；一帧阴影环放 **25 m 网格**加速。31 帧 × 285 环 ≈ 861.6 KB。
4. **路线**：校园路网 **613 条无向边 / 474 个节点 / 4 个连通分量 / 143 个独立回路**（`E−V+C`）；Python 侧手写 **heapq Dijkstra**；最快 = 边长，阴凉 = `边长 × (1 + 6.0 × 暴晒比例)`。
5. **任意两点现场算路**：`data/graph.js`（101.2 KB）把全路网（边长毫米精度）+ **31 帧 × 613 条边的暴晒千分比（0–1000）** + **53 个校园地名**发给浏览器；`js/router.js`（219 行）用**二叉堆**在页面里跑同一套 Dijkstra，吸附上限 **120 米**，只在**最大连通分量的 466 个节点**上吸附；零依赖、`file://` 可用、不发请求。
6. **换算**：`阴影米数 = 长度 − 暴晒分钟 × 60 × 1.25`（`WALK_SPEED = 1.25 m/s` ⇒ 每分钟 75 米），前端 `CORE.shadeMeters()`；这个换算可一条算式复算（14:00：1113 − 14.0×75 = 63 m ≈ 6%）。
7. **双实现一致性**：冒烟测试对 **2 × 31 = 62 个「起终点 × 帧」组合**逐个对拍 JS 现场算 vs Python 预计算，最大差 **0 米 / ≤0.05 分钟**——所以"现场算"和 PPT 上的数是同一套算法。
8. **低置信度**：太阳 < 15° 的 5 帧亮黄条；< 3° 不画阴影。
9. **测试**：`node tools/smoke.js` **90 条断言**，含 6 条校园边界回归、17 条算路断言（含 4 条地图点选）（同点提示、任意两算、往返对称、5 公里外拒绝、62 组合对拍）与文案精度锁定。
